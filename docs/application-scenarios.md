# FOLIO 应用场景分类

先问「人们为什么需要这张图或这段视频，要完成什么事？」。一级入口描述目的；发布平台、内容形式、画风和制作工具留在其他检索信息中。

| id           | 场景           | 常见需求                               |
| ------------ | -------------- | -------------------------------------- |
| identity     | 展示自己       | 头像、职业形象、自我介绍、求职作品展示 |
| memory       | 记录生活       | 旅行纪念、家庭与宠物、日常照片转绘     |
| feeling      | 表达心意       | 祝福、感谢、思念、陪伴、心情分享       |
| knowledge    | 讲清知识       | 概念解释、历史讲解、信息关系、操作教学 |
| promotion    | 介绍产品       | 商品特点、应用功能、服务效果、品牌识别 |
| announcement | 发布消息       | 活动通知、新品发布、节日安排、公共倡议 |
| opinion      | 表达观点       | 观察、态度、生活感悟、幽默与视觉隐喻   |
| story        | 讲述故事       | 人物关系、故事场景、分镜、连续叙事     |
| concept      | 构思角色与世界 | 角色设定、游戏世界、动画视觉、空间构想 |

## 归类规则

1. `category` 是最直接的主要用途；`scenarios` 的第一项与它一致，可补充有明确适配理由的次要用途。避免把通用风格塞进所有场景。
2. 能帮助读懂信息的画面归「讲清知识」；促使观众了解商品或服务归「介绍产品」；重点是让人注意到一条消息归「发布消息」。按任务选择，不能只因画面有文字就归消息或知识。
3. 个人形象和自我介绍归「展示自己」；保留已发生的经历归「记录生活」；对某个人传递情绪和祝福归「表达心意」。人物出现在图里并不足以归展示自己。
4. 叙事场景和分镜归「讲述故事」；角色形象与世界视觉的探索归「构思角色与世界」。一条可同时适配这两个用途。
5. 水墨、手绘、电影感等是风格；海报、绘本、短片等是形式；代码是制作方法；朋友圈、电商、自媒体是渠道或经营环境。它们继续可被搜索，不作为一级场景。
6. 通用风格的用途是编辑推荐，不能写成原作者声明。保留原文、作者、来源和可替换槽位；不要为符合场景编造产品、知识或故事内容。

例如：072「信息图鉴」用于讲清知识；115「清雅证件照」用于展示自己；110「旅行手帐对半」用于记录生活；111「月下清梦」用于表达心意；058「茶叶窗外主图」用于介绍产品；454「逐帧发布片」用于发布消息；050「动物警示 meme」用于表达观点；080「一张图长出故事板」用于讲述故事。

## 数据和兼容性

唯一编辑源是 `skills/folio-style/data/prompts.json`，数据版本为 2，场景分类版本为 1。网站、CLI、条目 Markdown 和目录共用 `scenarios`，筛选和搜索都包含次要场景。目录会在多个场景重复引用同一编号，各类数量不可相加。

视频保留原有 `use` 字段作为第二层形式筛选，与场景取交集。原 `category` 值保存在 `visualCategory`，仅用于迁移追溯，不再是浏览入口。旧分类 ID 的 `--category` 调用需改用新场景 ID；找旧风格请用 `--search`。
