# FOLIO 科普漫画采集规则

2026-10-09 用户澄清：以后找图偏向泛知识／科普漫画。调整的是搜索与选材方向，内容继续加入原有图鉴。

## 搜索与筛选

优先搜索这些类型：

- **连续科普漫画**：多格或多页，有人物的提问、理解过程与知识解释。
- **单页知识漫画**：用人物、对白、箭头、结构示意或对照讲清一个问题。
- **可复用的科普画风**：角色、线条、色板与版式能跨选题持续使用，适合知识账号的系列内容。
- **生活与自然科学的故事场景**：机制、步骤和关系是画面的主要内容，背景与道具为解释服务。

中文线索可用“科普漫画、知识漫画、原理图解、知识解释、连续分镜”；英文线索可用“science comic、educational comic、explainer comic、comic infographic”。依据实际结果细化主题，不机械堆砌关键词。一般人像、摄影与纯氛围图优先级降低，已有内容保留。

判断一张图是否合适，先问“它通过画面解释了什么知识，能否用于知识账号的一期内容”。只有漫画外观但没有知识表达的作品，不因画风相近就优先录入。成套分镜、人物一致、场景丰富、可替换主体或内容的完整提示词优先。没有固定数量或比例配额；合格素材不足时如实报告。

## 来源与录入

每个候选保留原帖、作者、完整提示词和预览来源；核对原文、图像对应关系及重复记录。画风参考与实际录入分开：没有完整提示词的代表作品仅作参考，不占用正式提示词编号，不计作新增。参考具体自媒体账号时，保留原创作品或官方说明链接；编辑归纳不能说成该账号公开的官方提示词。

公开读取继续使用公开 HTTP 来源，不引入用户的 X 登录 Cookie 或 Grok 账号 session。特定语言、对象、模型或上传要求按原文保留；需要改编时明确说明。知识事实与编辑推断分开，不能把画面内容自动当作已核实事实。

通过核验的提示词只追加到 `skills/folio-style/data/prompts.json`，保留原文、作者、来源与稳定编号。用 `npm run data:sync` 生成网站 JSON、单条文件与目录，再用 `npm run data:check` 核验。沿用现有应用场景分类，不新增独立“科普运营”功能。

这份规则保存后续更新的偏好，本身不代表已经采集新数据或创建自动采集任务。
